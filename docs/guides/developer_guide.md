# Developer guide

> [Version française](developer_guide.fr.md) | English version

Practical guide for working on the `radar-core` / `radar-audit` codebase.
For the contribution workflow (branches, commits, pull requests), see
[`CONTRIBUTING.md`](../../CONTRIBUTING.md). For the overall system design,
see [`docs/system-design.md`](../system-design.md) and the per-component
architecture docs in [`docs/architecture/`](../architecture/).

## Prerequisites

- Python 3.12+
- [`uv`](https://docs.astral.sh/uv/) (manages the workspace, dependencies, and virtual environment)
- A database reachable via a `RADAR_DATABASE_URL` connection string (SQLite is enough for local development)

## Workspace layout

This repository is a `uv` workspace with two packages:

- `radar-core`: the shared data model (SQLModel) and Alembic migrations
- `radar-audit`: the tool orchestration and normalization engine, exposed as the `radar-audit` CLI

```bash
uv sync
```

installs both packages and their dependency groups into a single workspace virtual environment.

## Database and migrations

Set `RADAR_DATABASE_URL` before running anything that touches the database, for example:

```bash
export RADAR_DATABASE_URL="sqlite:///./radar.db"
```

Apply migrations:

```bash
uv run --package radar-core alembic -c radar-core/alembic.ini upgrade head
```

Create a new migration after changing a model in `radar-core/src/radar_core/models/`:

```bash
uv run --package radar-core alembic -c radar-core/alembic.ini revision --autogenerate -m "describe the change"
```

Always review autogenerated migrations before committing them.

## Running the audit engine

`radar-audit` reads a `portfolio.yaml` file listing the repositories to audit:

```yaml
repos_root: ~/projets
repositories:
  - name: some-repo
  - name: another-repo
```

Preview the plan for a repository without running any tool:

```bash
uv run radar-audit run some-repo --dry-run
```

Run a real audit (writes results to the database, requires `RADAR_DATABASE_URL`):

```bash
uv run radar-audit run some-repo
# or, for every repository listed in portfolio.yaml:
uv run radar-audit run --all
```

By default the CLI reads `radar-audit/portfolio.yaml`; pass `--config` to point elsewhere.

## Tests

```bash
uv run --package radar-core pytest
uv run --package radar-audit pytest
```

Some `radar-audit` tests are marked `slow` (real `npx`/`npm` fetches that need network access) and are excluded by default in CI-like environments; run `pytest -m slow` explicitly to include them.

## Code quality gates

`ruff` (lint + format) and `mypy --strict` run on both packages via pre-commit hooks (`.pre-commit-config.yaml`). There is no CI pipeline yet enforcing these remotely (see [`docs/roadmap.md`](../roadmap.md)). Install and run the hooks locally before opening a pull request:

```bash
uv run pre-commit install
uv run pre-commit run --all-files
```

## Adding a new tool runner

Each normalization increment (one per Quality Framework category, see [`docs/quality-framework.md`](../quality-framework.md)) follows the same shape:

1. Implement a `ToolRunner` in `radar-audit/src/radar_audit/runners/`, invoking the external tool and returning its raw output
2. Add a normalizer that maps the raw output to a criterion score
3. Register the runner in `DEFAULT_RUNNERS` in `radar-audit/src/radar_audit/cli.py`
4. Cover both with tests mirroring the source layout under `radar-audit/tests/`
